# 07 - UI 组件库

## 概述

`packages/ui` 是一个共享的 React 组件库，目前只包含一个 `Button` 组件，但它的结构设计是可扩展的——你可以轻松添加更多组件。

## 目录结构

```
packages/ui/
├── src/
│   ├── index.ts          # 统一导出入口
│   └── Button.tsx        # Button 组件实现
├── package.json
└── tsconfig.json
```

**设计理念**：每个组件一个文件，通过 `index.ts` 统一导出。随着组件增多，结构变为：

```
packages/ui/src/
├── index.ts
├── Button.tsx
├── Input.tsx
├── Modal.tsx
├── Card.tsx
└── ...
```

## 源码解析

### index.ts — 统一导出

```typescript
// packages/ui/src/index.ts
export { Button } from "./Button";
```

这是一个**barrel file（桶文件）**，作用是提供一个统一的导入入口。使用者只需要：

```typescript
import { Button } from "@monorepo/ui";
```

而不需要：

```typescript
import { Button } from "@monorepo/ui/src/Button";  // 不好，暴露内部结构
```

### Button.tsx — 组件实现

```tsx
// packages/ui/src/Button.tsx
import React from "react";

interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: "primary" | "secondary";
}

export function Button({
  variant = "primary",
  className = "",
  children,
  ...props
}: ButtonProps) {
  const base = "px-4 py-2 rounded font-medium transition-colors cursor-pointer disabled:opacity-50";
  const styles =
    variant === "primary"
      ? "bg-blue-600 text-white hover:bg-blue-700"
      : "bg-gray-200 text-gray-800 hover:bg-gray-300";

  return (
    <button className={`${base} ${styles} ${className}`} {...props}>
      {children}
    </button>
  );
}
```

### 逐行解析

#### `extends React.ButtonHTMLAttributes<HTMLButtonElement>`

```typescript
interface ButtonProps extends React.ButtonHTMLAttributes<HTMLButtonElement> {
  variant?: "primary" | "secondary";
}
```

- `extends React.ButtonHTMLAttributes<HTMLButtonElement>` 继承原生 `<button>` 的所有属性
- 所以 `onClick`、`disabled`、`type`、`className` 等原生属性自动可用
- 只需要声明**额外的自定义属性**：`variant`

这是 React 组件设计的最佳实践——**继承原生属性，只扩展需要的部分**。

#### `...props` — 属性展开

```tsx
<button {...props}>
```

将除了 `variant`、`className`、`children` 之外的所有属性传递给原生 `<button>`。这样使用者可以直接传入 `onClick`、`disabled` 等。

#### `variant` — 变体模式

```typescript
variant?: "primary" | "secondary"
```

这是组件库中常见的**变体模式**。通过一个 `variant` prop 让组件呈现不同的样式，而不是创建 `PrimaryButton`、`SecondaryButton` 等多个组件。

## package.json 中的 peerDependencies

```json
{
  "dependencies": {
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  },
  "peerDependencies": {
    "react": ">=18.0.0"
  }
}
```

### dependencies vs peerDependencies

| | `dependencies` | `peerDependencies` |
|---|---|---|
| 含义 | 包自己安装的依赖 | 期望使用者已经安装的依赖 |
| 场景 | 工具库的内部依赖 | UI 框架、React 等基础库 |

这里 React 同时出现在 `dependencies` 和 `peerDependencies` 中：

- **`dependencies`** — 确保 pnpm 安装 React（用于开发时编译）
- **`peerDependencies`** — 告诉使用者"你需要安装 React >= 18"

> `peerDependencies` 中的 `>=18.0.0` 表示 React 18 和 19 都可以用，而 `dependencies` 中的 `^19.0.0` 是本项目实际开发时使用的版本。

## 样式策略

当前 Button 组件使用的是**纯 CSS 类名**（类似 Tailwind CSS 的风格）：

```tsx
const base = "px-4 py-2 rounded font-medium ...";
```

这意味着：

1. 使用这个组件库的项目需要引入对应的 CSS 框架（如 Tailwind CSS）
2. 或者你需要将这些类替换为项目自己的 CSS 类名

**可选的改进方案**：

| 方案 | 优点 | 缺点 |
|------|------|------|
| CSS-in-JS（styled-components） | 样式封装在组件内 | 包体积增大 |
| CSS Modules | 作用域隔离，无运行时开销 | 需要构建配置 |
| Tailwind 类名（当前方案） | 灵活，与项目样式一致 | 依赖外部 CSS 框架 |
| CSS 变量 | 可定制主题 | 需要使用者定义变量 |

## 使用方式

在 `apps/web` 中使用 Button：

```tsx
// apps/web/src/main.tsx
import { Button } from "@monorepo/ui";

function App() {
  return (
    <div>
      <Button onClick={() => alert("Hello!")}>
        Click me
      </Button>

      <Button variant="secondary">
        Secondary
      </Button>

      <Button disabled>
        Disabled
      </Button>
    </div>
  );
}
```

## 总结

- UI 包采用"一组件一文件 + barrel 导出"的结构
- 组件继承原生 HTML 属性，只扩展自定义属性
- `variant` 模式是组件库常用的样式切换方式
- `peerDependencies` 声明对 React 的版本要求
