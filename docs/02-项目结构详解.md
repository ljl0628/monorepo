# 02 - 项目结构详解

## 目录总览

```
monorepo/
├── apps/                    # 应用层 —— 可独立运行的项目
│   ├── web/                  #   前端 Web 应用（React + Vite）
│   └── server/               #   后端 API 服务（Express）
├── packages/                 # 包层 —— 供应用和其他包使用的库
│   ├── shared/               #   共享类型与工具函数
│   └── ui/                   #   共享 React 组件库
├── docs/                     # 教学文档
├── package.json              # 根 package.json（workspace 管理）
├── pnpm-workspace.yaml       # pnpm workspace 定义
├── turbo.json                # Turborepo 任务配置
├── tsconfig.json             # 根 TypeScript 配置
└── CLAUDE.md                  # 项目说明文件
```

## apps vs packages：关键区别

很多初学者会困惑：**应用（apps）和包（packages）有什么区别？**

### 应用（apps/）

**应用是可以独立运行的程序。**

- `apps/web` → 浏览器中打开的前端页面
- `apps/server` → 在 Node.js 中运行的后端服务

它们的特点：
- 有自己的入口文件（`src/main.tsx`、`src/index.ts`）
- 可以独立启动（`pnpm dev:web`、`pnpm dev:server`）
- 依赖 packages 中的库
- **不会被其他包依赖**（它们是树的"叶子节点"）

### 包（packages/）

**包是可复用的代码库，不能独立运行。**

- `packages/shared` → 类型定义和工具函数
- `packages/ui` → React 按钮组件

它们的特点：
- 没有入口文件（只有导出文件 `src/index.ts`）
- 不能独立启动（你不会 `pnpm dev` 一个工具库）
- 被 apps 或其他 packages 依赖
- 通过 `package.json` 的 `exports` 字段暴露给使用者

## 依赖关系图

```
@monorepo/shared
    ↑           ↑
    │           │
@monorepo/ui    @monorepo/server
    ↑
    │
@monorepo/web
```

用文字描述：

1. **`@monorepo/shared`** 是最底层的包，不依赖任何其他内部包
2. **`@monorepo/ui`** 依赖 `shared`（用于类型）
3. **`@monorepo/server`** 依赖 `shared`（用于 `createResponse`）
4. **`@monorepo/web`** 依赖 `shared` 和 `ui`（用于类型和组件）

> **重要原则**：依赖关系必须是**单向的、无环的**。永远不能出现 `shared` 依赖 `ui`，或者 `web` 依赖 `server` 的情况。

## 每个目录的 package.json 命名规范

所有子项目都有统一的命名前缀 `@monorepo/`：

```json
// packages/shared/package.json
{ "name": "@monorepo/shared" }

// packages/ui/package.json
{ "name": "@monorepo/ui" }

// apps/web/package.json
{ "name": "@monorepo/web" }

// apps/server/package.json
{ "name": "@monorepo/server" }
```

这个 `@monorepo/` 前缀叫做 **npm scope**（作用域），作用是：

- 表明这些包属于同一个组织/项目
- 避免与公开 npm 包重名（比如你不会和 npm 上的 `shared` 包冲突）
- 引用时更清晰：`import { Button } from "@monorepo/ui"`

## packages 与 apps 的"什么时候新建"指南

| 场景 | 放在哪里 | 示例 |
|------|----------|------|
| 新的前端页面 | `apps/` | `apps/admin-dashboard/` |
| 新的后端服务 | `apps/` | `apps/worker/` |
| 可复用的 React 组件 | `packages/` | `packages/ui/` |
| 共享的类型/接口 | `packages/` | `packages/shared/` |
| 共享的工具函数 | `packages/` | `packages/utils/` |
| API 客户端封装 | `packages/` | `packages/api-client/` |

**简单规则**：如果一个代码能被多个 app 使用，或者它不包含"入口"，就放 packages。如果能独立运行且对外提供服务，就放 apps。

## 总结

- `apps/` = 可独立运行的应用程序
- `packages/` = 可复用的代码库
- 依赖方向：`apps → packages → packages`，永远不能反向依赖
- 统一使用 `@monorepo/` 命名前缀
